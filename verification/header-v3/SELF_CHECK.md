## r4 限流停止与本地损坏恢复 · 2026-10-23

- 当前修订为 `header-v3-r4-20261023`。先前 r3 的 429/3600 秒仍在 1000ms 后重试、截断配置反复解析失败的首次复现保留在修复报告中。
- HTTP 429，或任何带 `Retry-After` 的失败响应，立即停止该请求，不再自动重试。有效秒数/HTTP 日期转换为人工续传提示，无有效值时提示先确认服务端冷却规则。响应体清理失败也不能恢复为过早重试。
- 服务端冷却的五种模拟响应均只请求一次；模拟下载已有三页后遭遇 429，页面保留、无成功报告，服务恢复后由新一次手动调用续传完成。没有向真实提供商制造 429，也没有真实等待一小时；不是公共服务或公网冷却的实测。
- 本地 `source.json` / `rpc.json` 截断时，两次续传都在联网前拒绝，原始字节保留，不生成 result；另验证截断页面在离线重放中拒绝。新错误说明保留原目录、解决存储问题后换新目录，README 区分网络续传与本地损坏。
- 这不是自动修复、原子写入或跨进程冷却锁。使用者仍须遵守提示，不能通过立即重开命令提前访问服务。
- Node `v18.0.0` 和 `v26.8.1`：各 **28 PASS、0 FAIL、0 SKIP**；不带档案时各 **16 PASS、0 FAIL、12 SKIP**。下面 r1/r2/r3 的数字均为历史结果，不计入本轮通过。
