# 验收标准与回传记录

目标是证明一个外部开发者能理解当前候选、独立获取公开证据、准确复算，并判断自己的场景是否需要它。禁止用“跑过作者的示例”替代需求验证，也不要把作者自检写成你的验收。

## A. 技术复算：明确通过什么

| 阶段 | 完成标准 | 结果标签 |
|---|---|---|
| 包完整性与基础向量 | 文件摘要一致；已知头、字节序、整数、Keccak 和只读 RPC 边界测试通过 | `PASS_PACKAGE_CHECKSUMS`；基础测试 16 PASS、12 个完整档案测试 SKIP |
| 自己取得公开数据 | 新目录；自己的环境；未读取作者缓存；固定 EVM 块与代码、17 个 view、4931 头及完整 continuity 一致 | `PASS_PUBLIC_REPLAY` |
| 离线恢复 | 保存整个输出目录；新进程或复制到新位置；无网络重放，S、raw hash、work、时间窗口和序列一致；来源标签、页面 URL 与观测时间格式通过检查 | `PASS_OFFLINE_REPLAY`；`sources.labelConsistency=CHECKED`，不证明来源真实性 |
| 故障拒绝与续传 | 十种缺失/篡改/不一致档案均失败；429 或服务端冷却立即停止不自动重试；截断配置/RPC JSON 保留原字节且反复续传都在联网前拒绝；模拟网络中断和冷却结束后手动续传通过；完成档案不覆盖 | 完整测试 28 PASS、0 FAIL、0 SKIP；模拟续传不计为新的公共获取 |
| 可选 RPC 对照 | 用另一实际提供商/自己的节点核对同一块；记录身份和原始输出 | `PASS_RPC_RECHECK`，不自动等于组织独立 |
| 首个自然检查点 | 固定样本尚未达到 973865 | **NOT_REACHED**，不能改为 PASS |

“自己的环境”至少是由验收者控制的独立机器或实例，不取得作者私有目录、密钥或后台快照，不依靠作者现场修改验证条件才通过。发现资料不足时记录它；需要作者修正后重跑是有效反馈，但应保留第一次失败和修订身份。

以下任一情况不得写技术验收 PASS：链 ID/块哈希/代码/整数/任一 continuity 字段不同；缺头或不足 100 个后继；使用 latest 替代固定样本；跳过失败条件；关键数据不可取得；把缓存 `result.json` 原样展示当作重放。

结果词义：

- `PASS_*`：仅覆盖该步骤。
- `FAIL`：证据与固定要求不一致，保留错误及复现材料。
- `BLOCKED_DATA`：公开接口不可用、限流或不提供历史状态，尚未完成；遵守服务端冷却后再手动续传。记录是否改用自己的节点；不通过更换同一服务域名提前重试。
- `NOT_RUN` / `NOT_REACHED`：没有执行或尚未自然到达，不能混入通过数。

包里的程序默认退出码 0 表示对应步骤成功，非零表示没有完成该步骤。成功也不消除协议说明中的锚点、RPC、选链、偏置与可用性假设。

## B. 最小消费者：与作者演示分开验收

先运行 `consume.mjs` 理解数据形状，再用自己的程序消费 `series.ndjson` 或已验证的 `S_wad`。至少保留链 ID、指数地址、EVM 块哈希和 Bitcoin 高度；使用整数，不把展示指数当可成交价格。

一个合格的最小消费者可以是历史风险路径比较、模拟结算或你现有系统中的一个只读模块。必须给出自己的输入、输出、使用目的和可复现方式；复制附带脚本换一个名字不算外部采用。不要为完成验收存入资金或新增仓位。

需求是否成立，与程序是否运行分开填写：

1. 你已有的具体问题是什么？为什么需要各方共同引用同一条未来路径？
2. 为什么本地 RNG、drand/VRF 或其他公开信标不能同样满足？不适合 WUJI 也是有效结论。
3. 你能接受怎样的确认延迟、停滞行为与月成本上限？需要谁保证数据及持续提交？
4. 继续使用的下一项可观察承诺是什么，例如纳入现有项目测试、指定维护人或承担具体预算？

只有技术 PASS、没有真实用途，结论应为“可复算，需求未验证”。这不是验收者失败，而是项目方向需要的证据。

## C. 本包未承担的验收

以下保持 **NOT_RUN**：独立安全审计、源代码到链上字节码的重新编译、完整 Bitcoin 区块/交易验证、全球最重链证明、最新状态健康、第二个签名 keeper 接手、作者离线连续运行、资金池压力/偿付审阅、钱包兼容、真实资金应用、自然检查点新样本及经济自养。

本地证据损坏不是网络续传通过项：保留旧目录与第一次失败，解决存储问题后在新目录重新获取，按 README 操作；不自动修补档案。

程序的 `operatorIndependence=NOT_ATTESTED` 不会自行升级为“独立”。外部身份、环境和工作范围由验收记录提供。报告中不包含私钥、助记词、密码、访问令牌、私有 RPC URL 或不必要的个人资料。

`sources.authenticity=NOT_ATTESTED` 也不会因标签相同而改变。文件摘要便于检查回传结果与档案是否对应，不能认证实际请求过哪个提供商或观测时间是否真实；自行一致改写全部标签仍超出离线工具的证明范围。
