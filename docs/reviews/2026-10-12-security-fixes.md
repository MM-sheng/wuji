# WUJI 安全复查修复验收（2026-10-12）

**R1–R4 的本地源码修复与回归验证已完成，尚未部署。** 基线为 `2454eb2`，分支
`codex/fix-mtp-window`。旧 Sepolia 合约和当前运行 keeper 均未改变；不可变合约必须重新部署才能采用新规则。
本报告接续 [原复查](2026-10-12-security-rescan.md)，不是声称原部署已安全或所有潜在问题均已消除。

## 修复结果

| 项目 | 实现 | 验证 |
|---|---|---|
| R1 待入场本金被旧亏损消耗、领取顺序分配损失 | 单独保留待入场净本金、已确定退款及已定价净退出款；不足偿付时自动永久终止，剩余存续价值按固定快照比例分配 | 原 99.7 退款用例先领、后领均实退 99.7；多个债权人顺序互换 fuzz；既有退出款完整保留 |
| R2 缺哈希的价格标记阻塞维护 | tip 标记同时保存哈希；补齐旧标记时验证价格相同；keeper 只把非零认证哈希用作锚点 | 真实 Bitcoin 头夹具、缺哈希中间锚点及旧池绕行回归 |
| R3 冻结价由调用顺序决定 | header-only 池使用已折叠 epoch 的认证历史价格；旧 relay 模式未开始 epoch 统一使用冻结 S；已开始的结算锁定价格 | 先冻结/先标记支付相同；缺数据时等待；按链上锚点恢复旧分支的 Node 测试 |
| R4 有效重组证明超过单笔 800 头 | 新增最多 256 头一段的公开可续证明；最终仍核对当前 tip 与 K+144 工作量 | 801 头反例可完成；并发候选、原链推进、字段篡改、难度/MTP/PoW 拒绝、真实重定向夹具 |

R1 保留固定本金、累加盈亏及价值上下界。净缺口先消耗实际 buffer；仍不足时才按
`floor(nominalValue × settlementAssets / settlementLiabilities)` 分摊。比例在终止时锁定。
这消除了先领取者侵占后领取者和新入场退款的行为，**没有消除模型本身的 floor overshoot 经济损失**。
退出手续费改在退出定价完成时入账，领取时支付预留净款；`claimableOf` 返回实际可领取净额。
没有增加管理员、升级、临时暂停或可变参数。

结算每笔交易最多访问 64 个账户，多个 epoch 共用预算，完成前不发布新累计量。
申请、退休和 sweep 等待结算完成；已预留退出款和已确定退款仍可领取。新增测试覆盖 130 个账户
分批处理、跨 epoch 共享预算、部分扫描中领取旧退出款，以及最终冻结尚未完成时领取退款。
UI/API 显示实际可领取金额、固定比例终止和分批结算状态。

keeper 在广播原始头前，按原始 SHA256d 哈希持久保存头数据；历史查找从链上锚点向父哈希回溯，
支持本地存档、按哈希的数据源和成功公开 raw-fold 交易输入。恢复交易可由
`ZK_HEADER_RECOVERY_TXS` 指定，最多 32 个。它不自动扫描全部 EVM 历史，也不从 proof-only 提交中恢复不存在的原始头。
若全部来源均缺少旧历史，关闭必须等待数据恢复，不接受新分支替代。

新增分段证明的每个完整状态都有链上哈希承诺，完整 proof 在公开事件中可恢复；候选不占独占槽、
不改变指数、不领取赏金。每个头仍经过原 PoW、链接、难度、MTP 和未来时间检查。
keeper 每轮提交一个 begin/extend/finish 步骤，以实际交易回执记录 proof，并在链上确认后持久保存；
不使用模拟时的返回值代替已上链的承诺。旧部署仍保留其单笔长度限制。

## 验证证据

- Solidity 全量默认套件：**325 通过、0 失败、24 跳过，35 个套件，退出 0**。计数包含继承夹具
  重复运行，并非 325 个独立漏洞检查。24 项为需单独配置的完整历史回放，本轮没有重跑。
- Node：indexer 与 terminal 全套 **154 通过、0 失败、1 跳过，退出 0**。跳过项需要同步后的全历史
  header 文件。旧分支恢复、分段封存、账户维护、显示及钱包已有测试均包括在内。
- 账户不变量改为真实现金覆盖所有存续价值、退款、预留净退出款及 buffer；不再把坏账或负账户
  当成资产。普通 ERC-20 假设仍然适用。
- 原 Node 首次全量在前端共享块断言处未找到预期文本而失败；后续核对文件与 HEAD 字节完全相同，未修改该共享块，
  再跑 indexer+terminal 全套通过。保留首次失败日志，未把该失败删去或降低断言。
- Foundry 隔离生产构建及 EIP-170/EIP-3860 尺寸检查通过；工厂创建池的 runtime 与相同参数直接
  构造的 runtime 逐字节相等，数据分片首字节为 STOP。
- 最大 256 个真实头的分段执行 gas 测试为 **4,622,438**；账户批次测试低于 keeper 的 8M 本地
  执行预算。这是本地 Prague 的执行测量，不能代替目标链实际总 gas 估算，尤其不能忽略状态创建成本。
- 另一对话框完成账户集合、准备金、部分结算及领取顺序的只读复核，未确认额外资金缺陷。
  这是内部交叉复核，不是独立第三方审计或形式化证明。

| 合约 | runtime 字节 | creation code 字节 |
|---|---:|---:|
| WujiAccounts | 23,646 | 25,309 |
| WujiAccountsFactory | 2,425 | 28,927 |
| WujiHeaderIndex | 12,234 | 15,526 |

工厂将固定的账户池 creation code 放入两个不可变数据合约：分片实际 runtime 为 12,655 和
12,656 字节（包括 STOP）。创建池时重组字节并追加参数，以避免工厂自身超过 EIP-170；池不是代理。
以后验证部署必须同时核对两个分片、工厂绑定和池的 runtime。池 runtime 剩余余量为 930 字节。

### 静态分析

Slither 分析成功（JSON `success:true`），产生 **146 条提示：High 3、Medium 20、Low 39、
Informational 84**，有发现时进程退出 255；不是零告警通过。

- High 3 是高度周期取模，被检测器误识别为弱随机数。代码用途为重定向/检查点判断。
- Medium 20：3 项先除后乘是向上取整、年龄查表与定点累计量；10 项严格相等是头规则、零值分支
  或普通代币到账检查；7 项局部变量使用 Solidity 默认零值或先完整赋值，再读取。
  新增候选目标高度/哈希相等检查正是拒绝原链扩展的约束，不应删除。
- Low 包括时间阈值、循环外部只读调用和事件重入提示；循环账户工作量已显式限制，header 步长也有
  上限。`RelayerRewards.credit` 的生产路径只做内部账务，不调用代币。工厂 treasury 零地址提示由
  下游池构造检查兜底，但部署仍应提前核验参数。
- 汇编三处为创建代码分片、复制和 CREATE；逐字节 runtime 等价测试覆盖重组。复杂度及 costly-loop
  提示保留；这些提示不是已经证实的攻击。扫描不能证明所有路径安全。

## 部署边界

本轮没有链上交易、签名、部署、资金迁移、运行 keeper 更新或公开发布。此前 MTP 修复的
Sepolia v2 指数 `0xf44F0FE640436d188fE1292a65D75CC1697C1a51` 及其三个池仍是旧版本；
它们不会自动获得本轮 R1–R4 修复。本轮也没有重新查询这些池的最新余额。

下一次测试网部署需使用本次完整源码，估算目标链 gas，核对工厂数据合约与全部绑定，更新隔离
keeper，再完成真实小额入场/退出和历史恢复演练。已存在的不可变资金池不能原地替换或由维护者
擅自搬走用户资金。全历史重放、目标链 gas、公开部署验收和正式独立审计不计入本轮完成项。
