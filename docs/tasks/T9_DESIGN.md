# T9 · 无管理员的深重组退出

2026-09-21 · 基线 `c8ea538` · 状态：源码候选、离线测试与本地部署验证；未替换既有测试网合约，待独立审阅。

## 1. 规则

深重组替换了已折叠历史后，任何人可记录异常。如果同一中继主链继续延伸、观察记录仍有效，且
中继高度达到观察时的基准高度再加 **144**，任何人可永久封存该指数。随后每个金库可独立关闭当前期：

- **本期预定边界已记录：** 使用该边界的 S 和本期 S₀ 计算原定份额，保留已有权利。
- **本期边界未记录：** 以 ½/½ 固定两侧份额。
- 不开下一期、不允许新铸造；原来已结算的期次及已经支付的款项不改变。配对赎回和已结算单边赎回继续使用原来的 5 bps 与舍入规则。

这是有证据门槛的不可逆终止，不是管理员暂停键、重写历史或自动恢复旧指数。没有新增所有者、参数修改权或资产提取权限。
144 是**测试候选参数**，按目标平均出块速度约一天，但没有日历期限保证，也没有已证明的经济安全性。
主网不得仅因测试通过就接受这个参数及 ½/½ 规则。

## 2. 为什么需要独立观察状态

`fold` 遇到错误时整笔交易回滚，所以不能一边让它 revert、一边期待它记住“从现在开始计时”。
新增 `observeReorg()` 是单独成功的交易；缺少观察记录时，哪怕不一致早已存在，也不能立即退出。

观察记录绑定六项：当前中继高度 h、截止高度 D、已折叠高度 L、已折叠哈希 H、观察时的中继头 B，
以及中继主链修订计数 r。截止高度固定为：

```text
D = max(h, L) + 144
```

使用 max 是为了覆盖**更短但工作量更高**的分叉；不能因新最佳链高度暂时降低而缩短保护范围。
这个计数测量的是中继高度进展，不是宿主链区块、墙钟时间或自某次失败交易以来的秒数。

`BitcoinRelay.reorgCount` 在每次更高工作量、且并非直接延伸当前 tip 的主链替换时增加。
等工作量分支、未胜出的旁链和正常延伸不增加。它记录的是本中继实际采纳过的换链，不证明全球主链。

观察有效当且仅当：

1. L/H 仍是指数最后折叠位置，且中继现在仍与它不一致。
2. 中继修订计数仍等于 r。
3. 中继在 h 高度的主链哈希仍等于 B。

任一条件失效，旧记录即无法用于退出。任何人在新的异常主链上重新观察都会重新计算 D。
重复提交仍有效的观察不会重置 D，避免旁观者通过刷调用无限拖延。

仅核对“现在仍不一致”和“旧观察头还在链上”是不够的：原链可能曾恢复，又被相同分支重新超过。
修订计数让这种即使没有人调用指数检查的中间恢复也使旧观察失效。选择保守规则后，替代链上的浅重组也会重置等待；
它减少连续性误判，但产生明确的拖延风险。

## 3. 状态转换与持有人权利

| 状态 | 折叠 / 新铸造 / 正常结算 | 退出能力 |
|---|---|---|
| 历史一致、未封存 | 保留原有边界与新鲜度条件 | 配对；旧期已结算单边 |
| 历史不一致、等待中 | 三者都拒绝；无需先调用 observe 才挡住新铸造 | 配对；旧期已结算单边 |
| 原链在封存前恢复 | 旧观察失效，正常路径可恢复 | 同原规则 |
| 观察有效且达到 D | 任何人可调用 `freeze()` | 封存后可逐个金库执行 `settleFrozen()` |
| 指数封存、金库未关闭 | 不再折叠、新铸造或普通开期 | 先关闭本库，再单边赎回 |
| 金库关闭 | 无新期，无新铸造，无再次结算 | 现存配对及冻结单边仍可赎回 |

封存前 `relay stale`、缺少数据、keeper 停机或自然长出块间隔**不会单独赋予退出资格**。
必须先有已折叠历史不一致的证据。封存一旦成功，即使原链以后回来，也不会重开指数或金库：
此时已有用户可能按退出份额拿走抵押，恢复原赔付会造成二次支付或资金缺口。

退出不依赖一次遍历全部金库。`freeze` 只封存一个指数，`settleFrozen` 只处理一个金库当前期；
其他金库和未结算的历史债权由各自持有人推动。中继仍接受独立 `submit`，便于保留公开链状态。
`submitAndFold` 在封存后整体回滚，不能借原子入口继续提交头；应使用独立中继入口。

## 4. “最后检查点”的精确定义

完整期按检查点间隔划分，首期可能更短；本期应使用的期末检查点始终是自己的预定边界。
因此不允许调用者选择“全局最新检查点”，也不使用前一期检查点来重置这期收益：

```text
if index.checkpointed(series.settlementHeight):
    finalShare = clamp(1/2 + [checkpointS(boundary)-series.s0]/2, 0, 1)
else:
    finalShare = 1/2
```

有积压未调用 `settle` 的旧金库，仍取**自己的**到期边界，即使指数另有更晚检查点。
期中才创建的金库没有完整首期，创建前或前期检查点不能拿来作为本期的记录；无自己的期末检查点就用 ½。
此前已冻结或支付的结果不回算。记录过的边界即使被新 Bitcoin 分支替换，也保留旧记录作为合同终止依据，
不宣称它变成了新分支的真实指数。这是不可撤销旧支付之后的退出取舍。

配对规则、抵押品单位、mint/redeem 费率、向 treasury 路由和舍入方向都不变。正常 ERC-20 假设下，
未结算时两侧供应匹配，终止时冻结互补份额，所以总抵押足以覆盖随后债权；拆单舍入尘埃仍可能留存。
正常路径的原有资金不变量原样保留；另外增加终止路径的守恒、偿付、零/一期开放状态与不可恢复性检查。

## 5. 故意制造退出的收益与攻击成本

**½/½ 能解决剩余单边债权的兑付，不保证经济中性。** 以同一抵押品计价，令 qY、qN 为攻击者持有的
整枚数量，N 为每对面值，a 为一个明确指定的正常结算反事实份额，忽略整数尘埃，则改变为 ½ 后的净收益差为：

```text
deltaV = N * (qY-qN) * (1/2-a) * (1-0.0005)
abs(gross deltaV) <= N * abs(qY-qN) / 2
```

例如 qY=10、qN=0、N=100，**假设正常到期会付 a=0.1**，½ 退出相对该结果多付 400 毛额、约 399.8 净额；
相应 YIN 持有人减少同额。不是从池外创造利润。这里的 a 不是 `values()` 当前显示，也不把尚未知晓的
正常期末结果当成攻击者已知信息。现实攻击分析应比较条件预期赔付或可执行的持仓成本，并纳入成功概率。

两侧等量持有对分配变化没有方向性收益，但可买入折价单边、使用外部杠杆或衍生品。
攻击者私人成本取决于已有分叉、矿池安排、弃块/隐瞒、宿主链审查、RPC 视图和外部头寸。
**等待 144 个中继高度不等于攻击者必然独自支付 144 个块的成本**；后续块可能由正常网络生产，
也可能已被挖出后批量中继。没有全球同步预言机，也没有 144 个真实日历间隔的保证。

选择 144 的理由只是给观察、独立跟随和撤销短暂分叉留出一个测试窗口，避免一个刚可见的冲突立即终止所有应用。
它不消除改变赔付的期权价值。更长等待增加锁定与中继成本，不能对无上限敞口给出普遍安全保证。
当前没有合约敞口上限，不宣称存在安全 TVL；主网必须独立审阅退出票价、等待参数与敞口政策。

### 明确保留的失败与拖延条件

- 替代链上的每次主链替换会使观察失效；攻击者可能借浅分叉反复延后退出。采用这一保守规则是连续性与活性的取舍。
- 没人提交后续头，就无法计满 D。`observe/freeze/settleFrozen` 没有新的专项赏金，用户或运营者承担 gas。
  权限开放不保证有人愿意付钱，也不保证中继能在交易 gas 限制内处理任意深分叉。
- 某金库、RPC 或前端没有及时观察到故障，会晚开始等待。主网观察者应独立读取相同 EVM 区块并核对修订与头部。
- SPV 锚点、区块体未验证、宿主链审查、发行人冻结和不受支持的 ERC-20 行为仍是边界；退出规则无法绕过它们。
- 封存后不能再赚新高度赏金；此前已经分配的赏金仍可领取。**未分配储备以及终止赎回产生的新费用可能永久留在旧路由/储备中**，
  当前没有管理者救援、旧工作追索新费用或跨部署迁移入口。此限制保留原费率和资金权限，必须披露。

## 6. 接口与操作顺序

新增中继 `reorgCount()`；指数 `historyConsistent()`、`observeReorg()`、`reorgNotice()`、
`frozenExitReady()`、`freeze()`、`frozen()`、`FROZEN_EXIT_DELAY()`；金库 `closed()`、`settleFrozen()`。
事件为 `ReorgObserved`、`Frozen`、`FrozenSettlement`，后者明确标记是否采用已记录期末结果。

对**采用此候选版本的新部署**：

1. 独立核对 relay/index/vault 的代码、绑定、链号、L/H 与当前主链，确认确有历史不一致。
2. 任意账户调用 `observeReorg()`，记录 `readyHeight`、修订计数与 tip 哈希。
3. 通过独立 `BitcoinRelay.submit` 继续追链。若主链再次替换，重新观察；若原链恢复，则无需退出。
4. `frozenExitReady()` 为真后，任意账户调用 `freeze()`；该动作不可逆。
5. 对目标金库调用 `settleFrozen()`，核对固定份额，然后持有人使用原来的 `redeemSettled()` 或 `redeemPair()`。

本轮没有让旧 keeper 自动发出封存交易，也没有修改已运行的旧前端。现有 v3 地址没有这些入口，
更改本地代码不能升级它们。新的公开测试网部署、终端/keeper 集成和完整退出演练是下一轮验收工作；
不应把此源码提交当作既有钱包已经获得退出保障。复核旧 v3 字节码时使用其原版本（如 `c8ea538`），
新源码与旧地址比较应失败，不应屏蔽新增差异。

## 7. 验证范围

新增单元/模糊测试覆盖：无异常与仅过期不能触发、缺观察、时钟无效、截止高度前一块与恰好截止、重复报告、
原链恢复、未观察到的恢复再换回、浅分叉重置、较短高工作量分支、观察头绑定、迟创建/积压金库选择正确检查点、
历史支付不变、配对继续退出、两位单边持有人实际净到账、整数守恒和关闭后永不重开。

另用现有**仅测试可用的低难度中继子类**实际挖头验证主链替换计数、144 高度等待、恢复后旧记录失效，
以及封存后的原子提交回滚/独立提交成功。没有向生产中继增加低难度模式。原来的真实主网头、难度重定向、
时间校验和金融不变量仍然运行。新增状态机在 64×60 步下混合转账、铸造、赎回、换链、观察、恢复、封存与关闭。
