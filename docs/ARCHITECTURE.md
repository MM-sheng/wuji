# WUJI · 架构与决定

> 无极生太极，太极生两仪。
> A market about nothing. Verifiable. Heartbeat: Bitcoin.

WUJI 是一个可验证的纯随机结算市场与公开基准，提供可由公开比特币区块头重算的指数。
“纯随机”指目标模型，不是对矿工无偏、与所有资产独立或投资收益的证明。两仪金库是使用该指数的示例应用。
数学边界与研究方法见 [WUJI_FOUNDATIONS.md](WUJI_FOUNDATIONS.md)。
任务规范见 [BTC_SOURCE.md](tasks/BTC_SOURCE.md)。

## 0. 原则

- 无 owner、管理员、暂停、升级、治理或项目代币。部署参数 immutable。
- 普通 ERC-20 行为假设下，配对毛赔付相加恒等于 NOTIONAL，固定基数分配，不凭空创造抵押品。
- 任何人可提交区块头、折叠指数或调用结算；索引器只是缓存。
- MIT；链下 Node/终端零第三方运行依赖；签名使用加密 keystore。
- 共享结算指数对应一族独立债权；不同链、抵押品、面值或期次不保证可互换，也不保证同步可用。
- 指数、即时结算份额、到期赔付和市场价格必须分开表达。即时份额不得作为借贷抵押价格源。

## 1. 指数

对比特币主链每个高度 h ≥ GENESIS_HEIGHT，在中继主链至少领先该高度 6 块后：

```
H = SHA256(SHA256(serialized 80-byte Bitcoin header))
R = SHA256(H)
delta = byteSum(R) - 4080
U += delta
S_wad = U * 12000000000000
displayIndex = 100 * exp(S_wad / 1e18)
```

H 是哈希函数的原始 32 字节输出；浏览器显示的比特币哈希将 H 反转。
R 对原始 H 哈希，不对显示字符串或其 ASCII 字节哈希。二次混合避免直接累加 PoW 哈希的零位偏差。
在 R 的 32 字节独立均匀的理想模型下，byteSum 为有限支持的离散分布（0…8160），均值 4080、
标准差约 418.04；不是截断正态分布。再哈希不能阻止矿工丢弃已知结果的区块。
每块等效波动约 0.50%，以平均 144 块/天估算日波动约 6%；这不是固定日波动承诺。
检查点高度为 GENESIS_HEIGHT + k×4320 − 1，每期平均约 30 天，实际历时随出块速度变化。
中继延迟只影响可用时间，不改变增量。链下浮点数只用于显示，合约整数 S 与赔付运算为准。

## 2. 两仪与检查点

- 1 对 = 1 YANG + 1 YIN；铸造抵押为 NOTIONAL，费率仍为 5 bps。
- `yangShare = clamp(1/2 + (S-S0)/2, 0, 1)`，YIN 取补数。固定基数，不复利放大。
- 这是相对开期 S0 的绝对位置截断，路径无关；触及边界后，若 S 返回区间，未结算份额也会返回。
  越过边界的过程不会改变其后的计算基数。
- 期次使用 Bitcoin `startHeight` / `settlementHeight`。
- 当 `index.lastHeight >= settlementHeight`，本期停止 mint。
- settle 读取预定高度的 checkpoint，不能任选更晚的 S。下一期边界固定递增。
- 配对随时可赎，已结算代币可单边赎；费率、向 treasury 路由、舍入方向均保留。
- 只有普通、非 rebasing、非转账扣费 ERC-20 受支持；mint 校验实际到账。

四个概念：`S` 是指数，`100e^S` 只是其展示；`g(S−S0)` 是即时结算份额；
`N·g(S_T−S0)` 是预定到期高度 T 的 YANG 毛赔付，YIN 为精确补数；`Q` 是二级市场可执行价格。
到期前 g 不是可随时单边兑现的报价。即使在零利率、无摩擦的公平模型下，期内估值也需要剩余随机性
下的条件期望赔付，通常不等于即时份额；真实 Q 还受流动性、抵押品与结算风险影响。
`values()` 展示的是 N 乘结算份额，不是市场价格，绝不可直接供借贷协议估值。

偿付定理的假设：抵押品如实报告余额、转账到账正确、无 rebasing/扣费，且不能在协议之外减少金库余额。
在这些假设与合约规则下，余额覆盖所有期次负债；配对毛赔付为 N，净到账另按固定费用和整数舍入计算。
测试验证这些假设内的资金不变量，不证明任意 ERC-20、抵押品美元价值或发行人可用性安全。

## 2b. 多抵押品

WujiVaultFactory 无许可创建 `(asset, notional)` 唯一金库。所有金库读同一 WujiIndex。
SeriesTokenDeployer 保留；代币名称带抵押品。不同抵押品分散流动性，工厂不构成资产审核。
对外标识应至少包含 `(chainId, collateral address, notional, seriesId, side)`，再以 vault/token 地址消歧。
简写 symbol 不是全局资产 ID。任意代币金库不承诺同等安全；WBNB 抵押保留 BNB 的价值敞口，稳定币保留发行人风险。

## 3. 应用边界

滚动金库、交易路由、持仓策略属于应用，尚未实现。现有有界期次金库不保证等待到盈利，
也不等同于永久现货。不得用配对偿付测试代替资产收益证明。

## 4. 合约

### BitcoinRelay

- 锚定可信主网 checkpoint header / height / epochStartTime / chainWork。
- 校验 80 字节、父链接、双 SHA256 PoW、nBits 解码有效性、非重定向高度难度相同。
- 每 2016 高度按父节点所在分支的 epoch 起止时间重算，时间跨度限制到 1/4–4 倍，编码回紧凑 nBits 后严格比较。
- 分叉由累计工作量选择，同工作量保留先到分支，较短但工作更多的分支也可成为主链。
- 存储哈希、父哈希、累计工作量和验证所需字段，不存完整 80 字节头。事件可用于追踪。
- `submit` 与 `fold` 分离，中继可被其他应用使用；fold 失败不阻止正确中继继续推进。
- 省略 MTP/未来时间限制，不验证交易和区块体；这是有明确信任边界的 SPV，不是完整节点。
- 目前没有 relay 新鲜度门槛，仍可能在追链期间折叠六深但过时的头；MTP、未来时间与追链门槛列入 T2b，未实现。
- 测试网部署的累计工作量从 checkpoint 自身工作量起算；共同的历史前缀偏移不影响任意两条分支比较。

### WujiIndex

- 从 relay 读取六深主链哈希，按高度折叠。默认每次 256，高度不会跳过。
- 保存 lastHeight 和该高度的 lastHash。fold 开始时核对主链哈希，包括 max=0 或无积压时。
- 已折叠高度发生变化时明确回滚 `deep Bitcoin reorg`；不自动撤销此前交易和结算。
- 构造金库最多折叠 256，高于此积压要求先独立 fold；mint/redeem 不做隐式积压处理。

### T1 经济模型：当前逐头中继，尚未包含 T2b / T10

控制测试中的执行 gas：常规提交约 68068/头；双币种折叠约 18342/高度；
原子提交+折叠的 16 高度批量约 78572/高度；首次单高度约 358266，后续单高度约 197062。
这些是测试体执行消耗，未含交易基础与 calldata gas，不是任意路径的上限。单次 claim 实测约 82462。
默认 keeper 跟随新块而不是等数小时凑批量，预算必须按单块估算；手续费归集、提款与服务资源另需留余量。

以 **250000 gas/高度** 作为常规运行情景预算（不是上限）、平均 144 高度/天、5 bps 费用全进储备：

| 假设网络与 gas 价 | 原生币/天成本 | 下一高度保本所需储备（原生币等值） | 每日带手续费的一级市场成交量（原生币等值） |
|---|---:|---:|---:|
| BSC，0.1 gwei | 0.0036 BNB | 0.25 BNB | 7.2 BNB |
| Ethereum L1，1 gwei | 0.036 ETH | 2.5 ETH | 72 ETH |
| Ethereum L1，5 gwei | 0.18 ETH | 12.5 ETH | 360 ETH |

公式：C = gas/高度 × gas价；每高度赏金约 R/10000，所以保本要求 R ≥ 10000C；维持储备的
每日费用来源约 144C，对应费基成交量 144C/0.0005（mint 与 redeem 分别按实际收费用量计数，非 DEX 成交量）。
例如仅作情景假设的 ETH=$3000 时，1 gwei 档约 $108/天、$216000/天费基成交量；不是实时币价或报价。
储备为其他代币时还需要兑换价值和流动性假设，不能把账面 Mock 余额当作运营资金。

零收入下储备近似按 (1−1/10000)^h 衰减，平均约 48.1 天减半（忽略最小单位舍入）。维持非零余额
不等于持续有利可图；独立提交者可能被别人抢走 fold 赏金，低成交量、抢跑、RPC/服务器和币价变化仍影响运行。
可复算脚本：`node scripts/keeper-economics.mjs`，GAS_PER_HEIGHT 可切换预算；所有币价/gas价均明确为假设。
T10 中的证明开销与预算只是未来目标，不能替代本轮实测。

## 5. 索引/API 与 keeper

- `SOURCE=bitcoin`，默认公共 Esplora 接口 mempool.space 和 blockstream.info。
- `BITCOIN_API` 可配置本地 Esplora；`BITCOIN_API_KIND=bitcoind-rest` 配合本地 Core REST 根 URL。
- `GENESIS_HEIGHT` 必填，数据文件为 `bitcoin-<genesis>.json`，与旧缓存分离。
- 核对 header 的显示哈希、父链接和六个后继头后发布。已发布历史变化时停止，不继续重写路径。
- 秒级指数展示按确认头时间发布；时间取该头及六后继时间的最大值，再与上一条发布时间取最大，避免比特币时间戳倒退导致时间索引错序。这是确定的展示约定，不是精确现实确认时间。
- `/head`、`/seconds`、`/blocks`、`/blockAt`、`/proof/:height` 保留。proof 返回原始头、H、R、delta、U、S_wad、来源链接。
- 新高度到达后终端刷新秒级缓存；块间指数展示不变，平均约十分钟不是倒计时承诺。
- 图表连续记录指数，不拼接各期 YANG/YIN 的重置值；模拟订单簿、成交和猴子账户不是代币市场价格或可执行流动性。
- keeper 比较来源与 relay 主链，寻找共同祖先，最多提交 24 个连续头，然后 fold，再 settle。
- 旧 SOURCE 默认 BSC 对照模式保留在 bsc-index.mjs / bsc-keeper.mjs，独立运行目录不会被新版本改动覆盖。

## 6. 验证与限制

- 夹具：798336–800363，共 2028 头；checkpoint 798335。跨越 800352 重定向，包含 800000 字节序已知向量。
- Solidity 与 Node 检查每一个 R 和累积 S；真实 relay 拒绝错误 PoW、难度和链接。
- 资金不变量保留原五项、64×60 调用深度与 fail_on_revert=true。资金状态测试使用显式标记的测试头 feeder，生产 PoW 另由真实夹具验证；不得把 feeder 当真实 PoW。
- 分叉测试使用测试专属低难度 subclass 来构造分支；生产部署没有低难度开关。
- 初版中继约 103034 gas/头；T2 常规奖励批量实测约 68069，条件与例外见 §8。后续奖励重做和 T2b 需重新测量。

## 目标栈（2026-09-20 定稿：最去中心化方案）

每一层选现有技术里**没有人能碰**的那个，并诚实标出剩余信任。这是主网的唯一形态。

| 层 | 选择 | 剩余信任 |
|---|---|---|
| 随机源 | 比特币 PoW | 比特币矿工整体 |
| 随机源验证 | SPV 中继，任何人提交，PoW 自证 | 一个部署时公开、任何人可核对的检查点区块头 |
| 结算链 | **以太坊 L1** | 以太坊验证者集合 |
| 抵押品 | **ETH 原生币**（工厂允许他人开其他金库，但正本是 ETH） | 无发行方 |
| 合约 | 不可变、无 owner、无代理、无预言机 | 零 |
| 手续费 | 不可变运行准备金，只能被 keeper 按赏金规则领取 | 零 |
| Keeper | 无许可 + 赏金 ⇒ 任何人 | 零 |
| 前端 | 单文件，IPFS，正本域名 **ENS**；可不经索引器直接读链 | ENS 合约 |
| 索引器 | 任何人跑，`wuji-verify` 一条命令核对 | 零（缓存） |
| 代码 | 公开多镜像 + IPFS 发布 + 可复现构建 + 浏览器验证源码 | 零 |
| 升级 | 没有。有 bug 就重新部署并社会迁移 | 零 |

- **创世**是唯一的人为时刻：提前公布创世高度与检查点，从公开 commit 用 CREATE2 部署，地址部署前可算；部署者从那一刻起与任何人平等。
- **L2 与其他链**：随机源来自比特币后，sequencer 只能审查不能影响路径，因此 L2/其他链可做**副本**（各自独立的 claim，不做桥）。以太坊 L1 是正本。
- **不可消除的边界**：比特币若改区块头规则，中继会停（与比特币自身规则固化同性质）；以太坊的质押集中度由多链副本稀释。
- **代价**：以太坊上每天 144 个区块头 + 折叠约 $65/天（1 gwei）。经济自养（T1 准备金 + 赏金）是活下去的条件，不是锦上添花。
- **为什么不在比特币链上**：比特币脚本读不到区块哈希、没有状态、没有循环与乘法、不能按公式分配资金——它是锁不是计算机。侧链/rollup/BitVM 各自加回联盟或桥的信任。合约链无关，未来若 BitVM 或 covenant 成熟可迁移，随机源不变。

## 7. 运营储备与按次赏金（T1 返工）

FeeRouter 是金库的 immutable treasury。`route(token)` 将该币种的 **100%** 费用通过
`fund(token, amount)` 记入 RelayerRewards 运营储备，不销毁，不留永久积分。费率仍为 5 bps。
任何人可捐赠；直接转账须先 `sync(token)` 才成为可用于未来工作的储备，捐赠不产生管理权或领取权。

每个成功折叠的高度，对本次选择的每种代币执行 `bounty = floor(reserve / 10000)`，然后从储备扣除。
批量调用逐高度依次扣减，与拆成单高度调用的结果完全一致。已分配未提取的金额不计入可用储备，
避免同一笔钱再次计赏。储备小于 10000 个最小单位时赏金为零；非零余额不保证足够支付 gas。

`fold(max, rewardTokens)` 将固定额度记给直接调用者；最多 256 高度、8 种排序去重的代币。
调用者明确选择要领取的币种，避免遍历无许可工厂的任意代币造成 gas/恶意回调阻塞。
未选择币种、零储备、或普通 `fold()` / `fold(max)` 完成的高度，**不产生以后补领的权利**。
合约为所有折叠维护连续的高度游标，拒绝重复或跳号登记；无新高度就无新赏金。原始头提交者不再另得奖励。

`claim(token)` 仅支付此前已固定的额度，不同步新资金、不读历史工作积分、不重新分摊未来费用。
资金关系为 `reserve + allocated == accounted token balance`；unsynced 直接转账可令实际余额更大。
`credit` 不调用 ERC-20；异常代币可以影响自己的入金/提款，不会阻塞其他币种或无赏金折叠。
守恒仍基于普通 ERC-20 假设，资产发行人和变更行为不由此消除。

`submitAndFold(headers,max,rewardTokens)` 是可选的原子入口：同一笔交易验证头并折叠，赏金记给外层调用者。
防止别人插入两笔操作之间拿走折叠赏金；不能保证赢得整笔交易的抢跑竞争。由此入口提交的头在 relay 的
`submitter(hash)` 中显示直接调用者 WujiIndex（用于观测，不是奖励归属）。原有独立入口仍可用；
深重组导致 fold 失败时，独立 submit 仍可推进 relay，而原子调用整体回滚。

构造顺序为 reserve → relay → index → router；reserve 只绑定预测的 index 地址与 GENESIS_HEIGHT，
没有 setter。部署脚本核对 CREATE 地址，测试网捐赠 MockUSDT/MockWBNB。主网目标中的原生 ETH 金库
和 CREATE2 创世部署仍需另行实现，不能由本轮 ERC-20 储备替代。

keeper 的 operations-reserve 模式只对操作者指定的 REWARD_TOKENS 计赏（可在启动时配置），正常跟进优先
原子调用，每次最多折叠 16 高度。遇到分叉需要追链时保持独立提交。默认每 144 个折叠高度尝试归集费用/
同步直接捐赠、提取固定赏金一次；ROUTE_EVERY_HEIGHTS / CLAIM_EVERY_HEIGHTS 是链下偏好，不是合约限制。
任何人仍可立即手动 route/sync/claim。失败币种独立记录，避免每轮为同一个失败提款反复花 gas。

旧版 :8790 的 lifetime-points/DEAD 合约不可升级，继续作为历史对照；新版本单独部署。
详见 [T1_RESERVE_REPORT.md](tasks/T1_RESERVE_REPORT.md)。

## 8. 中继存储压缩（T2）

父哈希按 PoW 数值序存储 224 位，并与 32 位节点 ID 合用一槽。主网 PoW 上限保证其高 32 位为零；
编码显式检查这个条件，解码恢复完整哈希。main[height] 仍保存完整原始哈希。
每个节点的 height/time/epochId/workerId 合计 128 位，相邻两个节点共享一槽，插入不覆盖另一半。

同一难度周期内每块工作量相同，累计工作量从分支自己的周期起点精确推导：
baseWork + (height − baseHeight) × blockWork。检查点可能在周期中间，此时它作为工作量起点，
但 retarget 使用真实周期起始时间；分叉到新的重定向点就建立独立周期记录。没有浮点或近似工作量。
